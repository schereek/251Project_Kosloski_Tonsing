Step 1: Recode column names, values, or formats that are in discordant (dates, etc)

To prepare the morbidity datasets for analysis, we compared the column names in the California (sim_ca) and Los Angeles (sim_la) files and found several inconsistencies. The same variables were labeled differently across datasets (for example, dt_dx vs. dt_diagnosis, dx_new vs. new_infections). To make them compatible, we created a clear mapping and renamed the LA variables to match the CA format. We also added a county column to the LA data so both files included the same geographic identifier. This standardization step was necessary to allow the two datasets to be combined into one complete morbidity dataset for the state.

After aligning the column names, we reviewed the variable values to make sure they were coded consistently across both datasets. Using the project codebook, we recoded the numeric race and ethnicity values in the California dataset into descriptive text labels so they matched the LA County format. We also converted the LA date variable from a SAS-style format (DDMONYYYY) to a standard date format (YYYY-MM-DD). These updates ensured that both datasets use the same categories and formats, which will make it easier to analyze and compare results once they are combined.

When comparing the column headers, we found one additional variable in the California dataset (time_int) that was not present in the Los Angeles County file. This column captured time intervals that were not needed for our current analysis, so we removed it to keep the datasets consistent before merging.

Step 2: Combine morbidity datasets into a single dataset

Now that both morbidity files used the same variable names and value formats, we combined them into one dataset using the bind_rows() function. This step let us put the statewide California records and the Los Angeles County records together in a single file so we can analyze all reported cases at once. The resulting combined dataset, saved as morbidity_all, includes all California and Los Angeles County record and will be used for aggregation and descriptive analyses in the following steps.

morbidity_all <- bind_rows(sim_ca_clean2, sim_la_clean2)

Step 3: Select demographic and geographic strata (s) of interest

For the next step, we identified the demographic and geographic strata we want to analyze. The dataset includes several variables that describe population subgroups, such as county, age group, sex, and race/ethnicity. For this analysis, we will focus on differences by sex, county, race/ethnicity, and age, since these are key factors that often influence disease patterns in public health data.

Step 4: Aggregate the data into a new dataframe to include only one row per strata of interest

Step 3: Create a rate metric and summarize to include only one row per strata of interest

After preparing the cleaned and collapsed population dataset, we joined it with the summarized morbidity dataset using the four shared variables: county, sex, race/ethnicity, and age category. This join ensured that population counts were aligned with corresponding morbidity totals for each demographic group.

We then created a new variable, infection_rate_per_100k, to express the number of new infections per 100,000 population. This rate allows comparisons of morbidity across counties, sexes, age groups, and race/ethnicity independent of population size. Each stratum within the variables of county, sex, race/ethnicity, and age category—now has a single summarized record that includes both case counts and the calculated infection rate.

# Join morbidity and population datasets into a new object
ca_id_rate <- full_join(
  morbidity_collapsed,
  ca_pop_collapsed,
  by = c("county", "sex", "race_ethnicity", "age_cat"))

# Create infection rate per 100,000 population
ca_id_rate <- ca_id_rate %>%
  mutate(
    infection_rate_per_100k = if_else(
      !is.na(population) & population > 0,
      (new_infections / population) * 100000,
      NA_real_))
